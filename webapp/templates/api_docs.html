BotC Script-PDF · API v1

Anmeldung

Jede Anfrage meldet sich per HTTP Basic Auth mit den normalen Login-Daten der Web-Oberfläche an: E-Mail-Adresse (bzw. Benutzername) und Passwort. Es gibt keine Sitzung und kein Token.

Authorization: Basic base64("email:passwort")
  • Nur freigeschaltete Konten haben Zugriff. Konten, die noch ihr Startpasswort ändern müssen, erhalten 403 password_change_required, bis das Passwort in der Web-Oberfläche geändert ist.
  • Fehlgeschlagene Anmeldungen zählen in dieselbe Sperre wie der Login im Browser: nach 5 Fehlversuchen 15 Minuten Pause (429 too_many_attempts).

Basic Auth überträgt das Passwort bei jeder Anfrage. Die API nur über HTTPS nutzen.

Ablauf

Eine PDF-Erzeugung dauert meist ein bis zwei Minuten. Deshalb arbeitet die API mit Aufträgen:

  1. POST /pdfs legt einen Auftrag an und antwortet sofort mit 202 und seiner ID.
  2. GET /pdfs/{id} liefert den Status, bis er done oder error ist (z. B. alle 2–5 Sekunden abfragen).
  3. GET /pdfs/{id}/download liefert das fertige PDF.

Die ID ist ein 32-stelliger Zufalls-Hash (z. B. 4a7b3aed8453478387a78243c1b73575), keine fortlaufende Nummer. Aufträge sieht nur das Konto, das sie angelegt hat; für alle anderen gibt es sie nicht (404).

Für einfache Skripte geht es auch in einem Schritt: POST /pdfs?wait=1 wartet bis zu {{ wait_max // 60 }} Minuten und antwortet direkt mit dem PDF.

POST

/api/v1/pdfs

Legt einen Auftrag an. Anfrage-Inhalt: JSON-Objekt, Content-Type: application/json ist Pflicht. Genau eine Quelle angeben: script, script_name oder script_id.

FeldTypBedeutung
scriptListeScript-JSON im Format des offiziellen Script-Tools. Der erste Eintrag {"id": "_meta", "name": …} liefert den Scriptnamen (ohne Namen kein Logo und kein Name auf dem PDF).
script_nameTextScript per Namen: zuerst unter den bereits geladenen Scripts, sonst auf botcscripts.com (beste Übereinstimmung, neueste Version).
script_idZahlGenau eine Script-Version auf botcscripts.com (deren interne Nummer pk).
optionsObjektOptional, siehe unten.

options

OptionTypStandardBedeutung
name_colorText"#000000"Schriftfarbe des Scriptnamens als Hex-Wert.
logo_descriptionText""Beschreibung für ein neues Logo, max. 500 Zeichen.
logo_providerText"pollinations""pollinations" (kostenlos) oder "openai" (nur wenn auf dem Server eingerichtet; für normale Benutzer begrenzt, siehe Grenzen).

GET

/api/v1/pdfs/{id}

Liefert den aktuellen Stand des Auftrags als Auftrags-Objekt (200). Unbekannte, abgelaufene oder fremde Aufträge: 404 not_found.

{
  "id": "4a7b3aed8453478387a78243c1b73575",
  "status": "done",
  "message": "Fertig.",
  "partial": false,
  "filename": "Trust.pdf",
  "log": ["Gefunden: 'Trust' (Trust.json)", "…", "Finales PDF gespeichert: …"],
  "status_url": "/api/v1/pdfs/4a7b3aed8453478387a78243c1b73575",
  "download_url": "/api/v1/pdfs/4a7b3aed8453478387a78243c1b73575/download"
}
GET

/api/v1/pdfs/{id}/download

Liefert das Ergebnis als Datei-Download (Content-Disposition: attachment).

  • 200 mit application/pdf: das doppelseitige Script-PDF.
  • 200 mit application/zip, wenn partial true ist: Name und Logo konnten nicht eingefügt werden, das ZIP enthält Vorder- und Rückseite ohne Branding.
  • 409 not_ready solange der Auftrag läuft, 409 job_failed wenn er fehlgeschlagen ist.

Fehler

Fehler kommen immer als JSON mit lesbarer Meldung und einem festen Code zum Auswerten:

{ "error": "Bitte genau eines angeben: script, script_name oder script_id.", "code": "invalid_source" }
StatusCodeBedeutung
400invalid_jsonInhalt ist kein JSON-Objekt.
400invalid_sourceKeine oder mehrere Quellen angegeben.
400invalid_fieldUnbekanntes Feld, falscher Typ oder ungültiger Wert (z. B. Farbe).
400invalid_scriptDie Script-JSON ist leer oder hat ein falsches Format.
401unauthorizedAnmeldung fehlt oder ist falsch.
403account_pendingKonto noch nicht freigeschaltet.
403password_change_requiredErst in der Web-Oberfläche ein eigenes Passwort setzen.

409not_readyDownload angefragt, aber der Auftrag läuft noch.

413too_largeAnfrage größer als {{ max_upload_mb }} MB.

Fehler, die erst während der Erzeugung auftreten (Script auf botcscripts.com nicht gefunden, Logo-Limit bei Suche per Name, …), erscheinen im Auftrags-Objekt als status: "error" mit message und code.

Beispiele

curl, in einem Schritt

curl -u 'anna@example.org:geheimes-passwort' \
     -H 'Content-Type: application/json' \
     -d '{"script_name": "Trust"}' \
     -o Trust.pdf --fail-with-body \
     '{{ base_url }}/pdfs?wait=1'

curl, mit eigener Script-JSON

curl -u 'anna@example.org:geheimes-passwort' \
     -H 'Content-Type: application/json' \
     -d "{\"script\": $(cat mein_script.json), \"options\": {\"blank_background\": true}}" \
     '{{ base_url }}/pdfs'

Python (requests), mit Status-Abfrage

import time
import requests

BASE = "{{ base_url }}"
auth = ("anna@example.org", "geheimes-passwort")

job = requests.post(f"{BASE}/pdfs", auth=auth, json={
    "script_name": "Trust",
    "options": {"logo_provider": "pollinations"},
}).json()

while job["status"] in ("queued", "running"):
    time.sleep(3)
    job = requests.get(f"{BASE}/pdfs/{job['id']}", auth=auth).json()

if job["status"] == "error":
    raise SystemExit(f"Fehlgeschlagen ({job['code']}): {job['message']}")

pdf = requests.get(f"{BASE}/pdfs/{job['id']}/download", auth=auth)
pdf.raise_for_status()
open(job["filename"], "wb").write(pdf.content)

Grenzen

  • Anfragen höchstens {{ max_upload_mb }} MB.
  • Aufträge laufen nacheinander. Ergebnisse werden 1 Stunde nach Fertigstellung gelöscht.
  • ?wait=1 wartet höchstens {{ wait_max // 60 }} Minuten. Ein vorgeschalteter Proxy muss so lange Verbindungen erlauben, sonst lieber den Status abfragen.
  • Neue Logos über OpenAI: normale Benutzer höchstens 5 in 7 Tagen, Admins unbegrenzt. Logos aus dem Cache und Pollinations zählen nicht. Dasselbe Limit gilt für Web-Oberfläche und API gemeinsam.
  • Fehlgeschlagene Anmeldungen: nach 5 Versuchen 15 Minuten Sperre.
